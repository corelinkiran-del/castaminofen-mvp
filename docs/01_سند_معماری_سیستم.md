# سند معماری سیستم - پلتفرم چندرسانه‌ای صوتی-تصویری

## ۱. دید کلی سیستم

### ۱.۱ هدف محصول
پلتفرم یکپارچه‌ای برای مصرف محتوای چندرسانه‌ای (صوت، ویدیو، کتاب صوتی) در بازار فارسی که جایگزینی ترکیبی از Spotify، YouTube، Castbox و Audible است.

### ۱.۲ اصول طراحی
- **Mobile-First**: تمام ویژگی‌ها برای موبایل طراحی شده‌اند
- **کارایی بالا**: تمرکز بر streaming و کاهش مصرف bandwidth
- **قابلیت توسعه**: معماری microservices برای رشد آینده
- **کاربرپسند**: تجربه مشابه Spotify/YouTube اما ساده‌تر

---

## ۲. معماری سطح بالا

### ۲.۱ معماری میکروسرویس‌ها
```
┌─────────────────────────────────────────┐
│         Client Layer (Frontend)         │
│  Mobile (React Native) + Web (Next.js)  │
└──────────────┬──────────────────────────┘
               │
┌──────────────┴──────────────────────────┐
│        API Gateway & Load Balancer      │
│     (Health Check, Rate Limiting)       │
└──────────────┬──────────────────────────┘
               │
┌──────────────┴──────────────────────────────────────────┐
│              Microservices Layer                        │
├──────────────────────────────────────────────────────────┤
│ • Auth Service          (JWT + OAuth2)                   │
│ • User Service          (Profile, Preferences)          │
│ • Content Service       (Metadata, Search)              │
│ • Media Service         (Streaming, Download)           │
│ • Notification Service  (Push Notifications)            │
│ • Payment Service       (Subscription, One-time)        │
│ • Creator Service       (Upload, Analytics)             │
│ • Recommendation Service (Future AI)                    │
└──────────────┬───────────────────────────────────────────┘
               │
┌──────────────┴───────────────────────────────────────────┐
│              Data Layer                                  │
├──────────────────────────────────────────────────────────┤
│ • PostgreSQL            (Relational Data)                │
│ • Redis                 (Cache, Session)                 │
│ • S3-Compatible Storage (Media Files)                    │
│ • CDN                   (Content Delivery)               │
│ • Elasticsearch         (Full-text Search)              │
└──────────────────────────────────────────────────────────┘
```

### ۲.۲ جریان داده
1. کاربر درخواست می‌کند (موبایل/وب)
2. API Gateway تطابق می‌یابد و درخواست را route می‌کند
3. سرویس متناسب درخواست را پردازش می‌کند
4. از Database/Cache داده می‌خواند یا می‌نویسد
5. Media Service برای streaming/download استفاده می‌شود
6. CDN پاسخ را تحویل می‌دهد

## ۳. سرویس‌های اصلی

### ۳.۱ Auth Service
**مسئولیت‌ها:**
- ثبت نام و ورود کاربران
- تولید و تحقق JWT tokens
- OAuth2 integration (Google, Apple)
- Refresh token management

**Endpoints:**
```
POST /api/auth/register
POST /api/auth/login
POST /api/auth/refresh-token
POST /api/auth/logout
GET  /api/auth/oauth/google
GET  /api/auth/oauth/apple
```

### ۳.۲ User Service
**مسئولیت‌ها:**
- مدیریت پروفایل کاربر
- ذخیره ترجیحات (dark mode، کیفیت streaming)
- تاریخچه شنیداری
- Follow و Library سازمان‌دهی

**Endpoints:**
```
GET    /api/users/{id}
PUT    /api/users/{id}
GET    /api/users/{id}/library
POST   /api/users/{id}/library/{contentId}
DELETE /api/users/{id}/library/{contentId}
GET    /api/users/{id}/history
GET    /api/users/{id}/follows
POST   /api/users/{id}/follows/{creatorId}
```

### ۳.۳ Content Service
**مسئولیت‌ها:**
- مدیریت متادیتای محتوا (پادکست، ویدیو، کتاب صوتی)
- ذخیره اطلاعات اپیزود/فصل
- جستجو و فیلتر کردن
- دسته‌بندی و تگ‌ها

**Endpoints:**
```
GET    /api/contents?type=podcast&category=education
GET    /api/contents/{id}
GET    /api/contents/{id}/episodes
GET    /api/contents/{id}/episodes/{episodeId}
POST   /api/search?q=keyword&type=podcast
```

### ۳.۴ Media Service
**مسئولیت‌ها:**
- Streaming محتوا (HLS/DASH)
- مدیریت دانلود آفلاین
- Adaptation کیفیت بر اساس bandwidth
- Tracking progress شنیداری

**Endpoints:**
```
GET    /api/media/{contentId}/stream
GET    /api/media/{contentId}/download
GET    /api/media/{contentId}/progress
POST   /api/media/{contentId}/progress
GET    /api/media/{contentId}/subtitle
```

### ۳.۵ Payment Service
**مسئولیت‌ها:**
- مدیریت subscription
- پردازش خریدهای تکی
- Integration با درگاه پرداخت ایرانی
- Invoice generation

**Endpoints:**
```
GET    /api/payments/subscription
POST   /api/payments/subscribe
POST   /api/payments/unsubscribe
GET    /api/payments/invoice/{id}
POST   /api/payments/purchase/{contentId}
```

### ۳.۶ Creator Service
**مسئولیت‌ها:**
- آپلود محتوا
- مدیریت اپیزودها
- Analytics و reporting
- Monetization settings

**Endpoints:**
```
POST   /api/creators/content/upload
POST   /api/creators/content/{id}/episode
PUT    /api/creators/content/{id}/episode/{episodeId}
DELETE /api/creators/content/{id}/episode/{episodeId}
GET    /api/creators/analytics/{contentId}
```

### ۳.۷ Notification Service
**مسئولیت‌ها:**
- ارسال push notifications
- Email notifications
- In-app notifications
- Notification preferences

**Endpoints:**
```
POST   /api/notifications/push-token
GET    /api/notifications
PATCH  /api/notifications/{id}/read
PATCH  /api/notifications/preferences
```

## ۴. طراحی دیتابیس

### ۴.۱ جداول اصلی

#### Users Table
```sql
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  phone VARCHAR(20),
  username VARCHAR(100) UNIQUE NOT NULL,
  password_hash VARCHAR(255),
  first_name VARCHAR(100),
  last_name VARCHAR(100),
  avatar_url VARCHAR(255),
  bio TEXT,
  preferred_language VARCHAR(10) DEFAULT 'fa',
  dark_mode BOOLEAN DEFAULT true,
  subscription_status VARCHAR(50) DEFAULT 'free', -- free, premium, creator
  subscription_end_date TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_creator BOOLEAN DEFAULT false,
  creator_status VARCHAR(50) -- pending, approved, rejected
);
```

#### Creators Table
```sql
CREATE TABLE creators (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL UNIQUE REFERENCES users(id),
  display_name VARCHAR(255) NOT NULL,
  description TEXT,
  profile_image_url VARCHAR(255),
  banner_image_url VARCHAR(255),
  verified BOOLEAN DEFAULT false,
  total_followers BIGINT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### Contents Table (Podcast, Audiobook, Video Series)
```sql
CREATE TABLE contents (
  id UUID PRIMARY KEY,
  creator_id UUID NOT NULL REFERENCES creators(id),
  title VARCHAR(255) NOT NULL,
  description TEXT,
  cover_image_url VARCHAR(255),
  category VARCHAR(50) NOT NULL, -- podcast, audiobook, video
  subcategory VARCHAR(100),
  language VARCHAR(10) DEFAULT 'fa',
  explicit BOOLEAN DEFAULT false,
  total_episodes BIGINT DEFAULT 0,
  total_duration BIGINT DEFAULT 0, -- seconds
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  published_at TIMESTAMP,
  status VARCHAR(50) DEFAULT 'draft' -- draft, published, archived
);
```

#### Episodes Table
```sql
CREATE TABLE episodes (
  id UUID PRIMARY KEY,
  content_id UUID NOT NULL REFERENCES contents(id),
  episode_number VARCHAR(50),
  title VARCHAR(255) NOT NULL,
  description TEXT,
  duration BIGINT NOT NULL, -- seconds
  file_url VARCHAR(255) NOT NULL,
  file_size BIGINT,
  thumbnail_url VARCHAR(255),
  published_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  transcript_url VARCHAR(255),
  status VARCHAR(50) DEFAULT 'published'
);
```

#### User_Progress Table (Continue Listening)
```sql
CREATE TABLE user_progress (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  episode_id UUID NOT NULL REFERENCES episodes(id),
  current_position BIGINT NOT NULL DEFAULT 0, -- milliseconds
  total_duration BIGINT NOT NULL,
  played_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  playback_speed DECIMAL(3,2) DEFAULT 1.0,
  is_completed BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, episode_id)
);
```

#### User_Library Table
```sql
CREATE TABLE user_library (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  content_id UUID NOT NULL REFERENCES contents(id),
  added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_downloaded BOOLEAN DEFAULT false,
  download_quality VARCHAR(50), -- high, medium, low
  UNIQUE(user_id, content_id)
);
```

#### User_Follows Table
```sql
CREATE TABLE user_follows (
  id UUID PRIMARY KEY,
  follower_id UUID NOT NULL REFERENCES users(id),
  following_id UUID NOT NULL REFERENCES users(id),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(follower_id, following_id)
);
```

#### Playlists Table
```sql
CREATE TABLE playlists (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  title VARCHAR(255) NOT NULL,
  description TEXT,
  cover_image_url VARCHAR(255),
  is_public BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### Playlist_Episodes Table
```sql
CREATE TABLE playlist_episodes (
  id UUID PRIMARY KEY,
  playlist_id UUID NOT NULL REFERENCES playlists(id),
  episode_id UUID NOT NULL REFERENCES episodes(id),
  position INTEGER NOT NULL,
  added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(playlist_id, episode_id)
);
```

#### Subscriptions Table
```sql
CREATE TABLE subscriptions (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  subscription_type VARCHAR(50) NOT NULL, -- monthly, yearly
  amount DECIMAL(10,2) NOT NULL,
  currency VARCHAR(3) DEFAULT 'IRR',
  status VARCHAR(50) DEFAULT 'active', -- active, cancelled, expired
  payment_method VARCHAR(50),
  transaction_id VARCHAR(255),
  started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP,
  cancelled_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### One_Time_Purchases Table
```sql
CREATE TABLE one_time_purchases (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  content_id UUID NOT NULL REFERENCES contents(id),
  amount DECIMAL(10,2) NOT NULL,
  currency VARCHAR(3) DEFAULT 'IRR',
  payment_method VARCHAR(50),
  transaction_id VARCHAR(255),
  purchased_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP
);
```

#### Downloads Table (Offline Management)
```sql
CREATE TABLE downloads (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  episode_id UUID NOT NULL REFERENCES episodes(id),
  file_path VARCHAR(500),
  file_size BIGINT,
  quality VARCHAR(50), -- high, medium, low
  status VARCHAR(50) DEFAULT 'pending', -- pending, downloading, completed, failed
  progress_percentage INTEGER DEFAULT 0,
  downloaded_at TIMESTAMP,
  expires_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP + INTERVAL '30 days',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### Notifications Table
```sql
CREATE TABLE notifications (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  type VARCHAR(50) NOT NULL, -- new_episode, follow, purchase, message
  title VARCHAR(255) NOT NULL,
  message TEXT,
  data JSONB,
  is_read BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  read_at TIMESTAMP
);
```

#### Creator_Analytics Table
```sql
CREATE TABLE creator_analytics (
  id UUID PRIMARY KEY,
  creator_id UUID NOT NULL REFERENCES creators(id),
  episode_id UUID NOT NULL REFERENCES episodes(id),
  date DATE NOT NULL,
  total_plays BIGINT DEFAULT 0,
  total_duration_played BIGINT DEFAULT 0,
  unique_listeners BIGINT DEFAULT 0,
  new_followers BIGINT DEFAULT 0,
  retention_rate DECIMAL(5,2),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(creator_id, episode_id, date)
);
```

## ۵. API Specification


```json
{
  "success": true,
  "data": {},
  "error": null,
  "timestamp": "2026-07-04T10:30:00Z",
```

```json
{
  "success": false,
  "data": null,

    "code": "INVALID_REQUEST",

    "details": {}
  }
}
```

```
GET /api/contents?page=1&limit=20&sort=created_at:desc

{

  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 500,
    "totalPages": 25
  }
}
```

## ۷. سناریوهای استفاده (Use Cases)

### ۷.۱ UC-001: شنیداری پادکست
**بازیگران:** کاربر، Backend API، Media Server
**Preconditions:** کاربر logged in است
**Flow:**
1. کاربر به لیست اپیزودها رسیدگی می‌کند
2. یک اپیزود انتخاب می‌کند
3. سیستم از Media Service درخواست streaming کند
4. Media Server HLS manifest را تحویل می‌دهد
5. کاربر شنیدار می‌شود

### ۷.۲ UC-002: دانلود آفلاین
**Preconditions:** اپیزود انتخاب شده، اتصال Internet
**Flow:**
1. کاربر دکمه دانلود را میزند
2. سیستم download request را ثبت می‌کند
3. Media Server فایل را دانلود می‌کند
4. کاربر بدون اینترنت می‌تواند دانلود شده را شنیده باشد

### ۷.۳ UC-003: Subscribe
**Preconditions:** کاربر free user است
**Flow:**
1. کاربر بر روی دکمه Subscribe کلیک می‌کند
2. سیستم به درگاه پرداخت متصل می‌شود
3. کاربر پرداخت را تکمیل می‌کند
4. Payment Service subscription را active می‌کند
5. کاربر premium features را unlock می‌کند
